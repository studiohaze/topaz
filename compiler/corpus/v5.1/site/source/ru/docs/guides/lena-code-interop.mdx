Lena Code — родственный продукт Топаза. Его конвертационные процессы могут
использовать Топаз как входной или выходной язык. Топаз фокусируется на малой
проверяемой поверхности исходника и детерминированном исполнении, а Lena Code
фокусируется на межъязыковых процессах конвертации.

## Примеры преобразований

### Rust → TypeScript

```rust
pub fn greet(name: &str) -> String {
    format!("Hello, {}!", name)
}
```

```typescript
export function greet(name: string): string {
  return `Hello, ${name}!`;
}
```

### Rust → Топаз

```rust
pub fn add(a: i32, b: i32) -> i32 {
    a + b
}
```

```topaz
function add(a: int, b: int) -> int {
    a + b
}
```

Эти примеры показывают форму interop-границы. Если целевой язык — Топаз, результат должен оставаться на канонической поверхности Топаза. Дифференциальные проверки run/build — инженерные гейты для поддержанных программ на Топазе. Когда этот сайт говорит о доказательстве, речь идёт ровно об этих проверках.

## Доступ

- Поведение самой Lena Code и поддерживаемые пары языков описаны на <a href="https://www.lenacode.com" target="_blank" rel="noopener noreferrer">lenacode.com</a>.
- Сконвертированный код на Топазе — обычный код на Топазе: парсите его, запускайте и для программ с выводом сравнивайте путь run с собранным артефактом.

## Ограничения

- Фрагменты Rust и TypeScript выше не принимаются парсером Топаза.
- Топаз не заявляет автоматический round-trip с произвольными внешними языками.
- Перенося логику в Топаз, держите в фокусе Result-first ошибки и pattern matching.
