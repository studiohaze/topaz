> **Примечание о версии**: эта документация отражает канонический синтаксис **Topaz v5.2** — строгого надмножества замороженного v5.1. Модули — новинка v5.2: см. [Модули и видимость](/ru/docs/concepts/modules).

Топаз — малый замкнутый язык для замысла приложения: один канонический способ сказать каждую вещь; пишут люди и агенты, проверяет тулчейн. Он читается как Python или TypeScript, но поверхность сознательно замкнута: у каждого замысла ровно одна каноническая форма, зафиксированная в спецификации v5.2. Кому язык подходит — и кому нет — см. [Почему Топаз?](/ru/docs/why-topaz).

Каждая программа на этой странице, показывающая вывод, выполняется верификатором сайта на тулчейне v0.3 — каждый блок вывода обязан байт в байт совпадать с записью реального запуска, — а остальные фрагменты проходят проверку парсером.

**Интероп с Lena Code** — Топаз входит в семейство продуктов STUDIO HAZE вместе с Lena Code. Он может служить и входным, и целевым языком в конвертационных процессах Lena Code, поэтому код на Топазе естественно проходит через эти процессы и возвращается обратно. Сам Топаз остаётся малым, замкнутым, Unicode-first языком, который люди и ИИ-агенты пишут одинаково, с дифференциальными проверками run/build для поддержанной поверхности.

## Первое доказательство: Unicode-first

Идентификаторы — Unicode начиная с лексера: кириллица здесь гражданин первого класса, и слова предметной области остаются на вашем языке, а не превращаются в латинизированные приближения:

```topaz
function greet(name: string, language: string) -> string {
    return match language {
        case "한국어" => "안녕하세요, {name}님!"
        case "Русский" => "Привет, {name}!"
        case _ => "Hello, {name}!"
    }
}

let 사용자 = "김토파즈"
print(greet(사용자, "한국어"))
print(greet("Topaz", "Русский"))
```

```text output
안녕하세요, 김토파즈님!
Привет, Topaz!
```

`사용자` — обычная переменная. Unicode-идентичность не «терпимый крайний случай»: идентификатор — ровно та последовательность скаляров, которую вы написали, без тихой нормализации (§1), а резолвер модулей отвергает похожие имена модулей между файлами по ключам exact, NFC/NFD и case-fold (§17).

## Четыре столпа

### Малая замкнутая поверхность

У каждого замысла один способ записи. Политику решает язык — `Result` для восстановимых ошибок, опционалы для отсутствия, `defer` для очистки — чтобы ни людям, ни агентам не приходилось решать это заново в каждом файле:

```topaz
function parsePort(raw: string) -> Result<int, string> {
    let n = toInt(raw) ?? -1
    if n < 1 {
        return Err("not a port: {raw}")
    }
    return Ok(n)
}

function startup(raw: string) -> Result<string, string> {
    defer print("config closed")
    let port = parsePort(raw)?
    return Ok("listening on {port}")
}

print("{startup("8080")}")
print("{startup("http")}")
```

```text output
config closed
Ok(listening on 8080)
config closed
Err(not a port: http)
```

Оператор `?` пробрасывает `Err`; `defer` выполняется на каждом пути выхода — поэтому `config closed` появляется в транскрипте дважды.

### Unicode-first идентичность

Доказано выше. Строки — последовательности скаляров Unicode без неявной нормализации: что написано, то и сравнивается (§1). API кластеров графем отложены до будущего решения v5 (§20, §22).

### Готовность к эпохе агентов

Спецификация, достаточно малая, чтобы агент держал её целиком; машинно-проверяемые профили; и документация, которая сама проверяется: каждый канонический фрагмент на этом сайте проходит проверку парсером, а исполняемые примеры выполняются с зафиксированным выводом. См. [как проверяется этот сайт](/ru/docs/status).

### Шаблоны с замыслом

Строки `sql`, `sh` и `path` — это шаблоны: структурированные значения, в которых части и интерполяции остаются раздельными, а не схлопываются в строку:

```topaz
let table = "users"
let q = sql"select * from {table} where active = {true}"
print("{q}")
```

```text output
<sql template, 3 part(s), 2 interpolation(s)>
```

Этот плейсхолдер — честное состояние v0.3: значение-шаблон существует, и ничего не было склеено; политики рендеринга по доменам (кавычки, экранирование) отложены до будущего решения v5. Безопасность остаётся грамматикой, а не дисциплиной.

## Типовая дисциплина, честно

По спецификации Топаз статически типизирован — аннотации, вывод типов и литеральные типы входят в зафиксированную поверхность v5.2:

```topaz
type TrafficLight = "red" | "yellow" | "green"

function next(light: TrafficLight) -> TrafficLight {
    return match light {
        case "red" => "green"
        case "green" => "yellow"
        case _ => "red"
    }
}
```

Однако статическая проверка типов — следующий трек компилятора: она **запланирована**, а не выпущена. Сегодня эта форма проходит парсер и резолвер модулей, а интерпретатор v0.3 обеспечивает контракты во время выполнения как динамические страховки (TPZ5xxx); задача чекера — превратить эти страховки в статическую диагностику. [Страница состояния](/ru/docs/status) отслеживает ровно эту границу.

## Что работает сегодня

v0.3 (выпущен 2026-06-12) выполняет Topaz v5.2 от начала до конца: Unicode-first лексер, полный парсер, многофайловый резолвер модулей и эталонный интерпретатор за `topaz run` — включая сопоставление с образцом, defer, concurrent и фолты с указателями на исходный код. До открытия исходного кода тулчейн живёт в закрытом CI; количества и проверки сайт публикует на странице [Состояние тулчейна](/ru/docs/status).

Первая программа — в руководстве [Начало работы](/ru/docs/getting-started): каждый транскрипт там записан с реального бинарника.

## Дорога вперёд — обозначенное видение

- **Проверка типов** — запланирована; следующий трек компилятора.
- **Эмиссия Rust** — целевая веха; никаких публичных заявлений до дифференциального тестирования против интерпретатора.
- **Дистрибуция** — придёт вместе с открытием исходного кода.
